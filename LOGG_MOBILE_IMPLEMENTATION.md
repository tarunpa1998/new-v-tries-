# Logg Mobile App — Complete AI Implementation Specification

> **For the AI executing this plan**: Read every section before writing a single
> line of code. This document is the single source of truth. Do not deviate
> from the architecture, folder structure, naming conventions, or design tokens
> described here. The existing web app (`frontend/`) and backend (`backend/`)
> are **never touched** — they stay exactly as they are.

## 0. Overview & Guiding Principles

| Item                         | Decision                                                                  |
| ---------------------------- | ------------------------------------------------------------------------- |
| App name                     | **Logg**                                                                  |
| Platforms                    | iOS 16+ and Android 12+ (API 31+)                                         |
| Framework                    | **Expo SDK 52** — Managed Workflow                                        |
| Language                     | **TypeScript 5.x — strict mode, zero `any`**                              |
| Navigation                   | **Expo Router v4** (file-based, like Next.js)                             |
| Data fetching                | **TanStack Query v5** (already used in web)                               |
| Forms                        | **React Hook Form v7 + Zod v4** (already used in web)                     |
| HTTP                         | **axios** (already used in web, adapted for native)                       |
| i18n                         | **i18next + react-i18next** (same 15 languages as web)                    |
| Monorepo tool                | **pnpm workspaces + Turborepo**                                           |
| Separate iOS/Android folders | **YES** — `apps/ios/` and `apps/android/` exist as **Expo bare workflow** |
| Design system                | **Completely separate from web** — new palette, typography, tokens        |
| Theme                        | **Full dark + light mode** with its own distinct token set                |
| Code reuse                   | Maximum: types, API client, utils, i18n — all shared via packages         |
| Backend                      | **Zero changes** — it already is a REST API                               |

## 2. Why Separate `apps/ios/` and `apps/android/`?

Even though Expo writes one codebase, having separate app roots gives:

- **Different `app.json`** per platform (bundle IDs, icons, splash screens)
- **Different native modules** if iOS ever needs something Android doesn't
- **Independent release cycles** — ship iOS hotfix without touching Android
- **Separate EAS project configs** (`eas.json`)
- **Platform-specific env vars** (Apple credentials vs Google keystore)
- **Different Fastlane lanes**

The **source code** (screens, components, hooks) is **shared** through
`packages/` — so there is exactly **one copy** of every screen, not two.
The app roots just wire things together differently per platform.

## 4. Design System — Mobile (Completely Separate from Web)

> **Critical rule**: The mobile app has its own design language. Do NOT copy
> colors or typography from the web. The web uses Tailwind + Radix; the mobile
> app uses its own design token system. They connect to the same backend API
> and share business logic — that's all.

## 6. Shared Packages — Implementation Details

### 6.1 `packages/api/src/client.ts`

The API client from `frontend/src/lib/api.ts` uses `localStorage` — that does
not exist in React Native. The mobile client uses `expo-secure-store` instead,
injected via a token-getter callback:

```typescript
// packages/api/src/client.ts

import axios, { type AxiosInstance } from "axios";

export type TokenGetter = () => Promise<string | null>;
export type WorkspaceIdGetter = () => Promise<string | null>;

export interface ApiClientConfig {
  baseURL: string;
  getToken: TokenGetter;
  getWorkspaceId: WorkspaceIdGetter;
  onUnauthorized?: () => void;
}

export function createApiClient(config: ApiClientConfig): AxiosInstance {
  const client = axios.create({ baseURL: config.baseURL });

  client.interceptors.request.use(async (reqConfig) => {
    const token = await config.getToken();
    if (token) reqConfig.headers.Authorization = `Bearer ${token}`;
    const workspaceId = await config.getWorkspaceId();
    if (workspaceId) reqConfig.headers["X-Workspace-Id"] = workspaceId;
    return reqConfig;
  });

  client.interceptors.response.use(
    (response) => response,
    (error) => {
      if (error.response?.status === 401) {
        config.onUnauthorized?.();
      }
      return Promise.reject(error);
    },
  );

  return client;
}
```

In the mobile app, it is wired up in `providers/QueryProvider.tsx` using
`expo-secure-store` as the token store.

```typescript
// Key differences from web i18n:
// 1. No LanguageDetector browser plugin — use expo-localization instead
// 2. All locale JSONs bundled (no lazy loading via import.meta.glob)
//    because React Native bundler doesn't support dynamic imports the same way
// 3. Language preference stored in expo-secure-store, not localStorage

import * as Localization from "expo-localization";
import * as SecureStore from "expo-secure-store";
import i18n from "i18next";
import { initReactI18next } from "react-i18next";

// Import ALL locale files (bundled at build time)
import en from "../locales/en.json";
import ptBR from "../locales/pt-BR.json";
// ... all 15

const LANG_KEY = "logg_language";

export async function initI18n() {
  // 1. Try user's saved preference
  const saved = await SecureStore.getItemAsync(LANG_KEY);
  // 2. Fall back to device language
  const device = Localization.getLocales()[0]?.languageTag ?? "en";
  const lng = resolveSupportedLang(saved ?? device);

  await i18n.use(initReactI18next).init({
    resources: {
      en: { translation: en },
      "pt-BR": { translation: ptBR } /* all 15 */,
    },
    lng,
    fallbackLng: "en",
    interpolation: { escapeValue: false },
  });
}

export async function changeLanguage(lang: SupportedLang) {
  await i18n.changeLanguage(lang);
  await SecureStore.setItemAsync(LANG_KEY, lang);
}
```

> **RTL Support**: `hi` (Hindi) and `ja` (Japanese) are LTR. All 15 languages
> are LTR so RTL is not needed. However, the layout engine must use

## 10. Auth Flow — Mobile

```
App Launch
    │
    ├─► No token in SecureStore → /auth/login
    │
    └─► Token found → validate via GET /api/users/me
              │
              ├─► Valid → load user → main app
              │
              └─► 401 → clear token → /auth/login

Login Screen:
  - Email + Password form (React Hook Form + Zod)
  - "Sign in with Biometrics" button (if registered, expo-local-authentication)
  - Error inline below inputs (not toast — per UX rules)
  - Loading state: button disabled + ActivityIndicator

2FA Screen (if required):
  - 6-digit OTP input (auto-advance between digits)
  - TOTP code or passkey (expo-local-authentication for passkey-backed 2FA)
  - Resend option

Biometric Registration (first time after login):
  - Bottom sheet: "Use Face ID / Fingerprint to sign in faster?"
  - Yes → expo-local-authentication.authenticateAsync() → if success, store token association
  - Skip → never show again for this device

Session Management:
  - Token stored in Keychain (iOS) / Keystore (Android) via expo-secure-store
  - App goes to background > 5 min → require biometric re-auth on foreground
  - Token expiry → silent refresh attempt → if fails → redirect to login
```

## 11. Offline Mode

```typescript
// mobile-src/lib/offline-queue.ts

// Strategy: Cache-first, sync in background
// 1. All GET requests: cache response in MMKV
// 2. All mutations (POST/PUT/PATCH/DELETE): if offline → queue to MMKV
// 3. On reconnect: drain queue in FIFO order
// 4. Conflict: server wins for GETs; show toast for failed mutations

// Libraries:
// - react-native-mmkv (fast synchronous key-value, replaces AsyncStorage)
// - @react-native-community/netinfo (network status)
// - TanStack Query: set networkMode: 'offlineFirst'
```

TanStack Query config for offline:

```typescript
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 1000 * 60 * 5, // 5 min
      gcTime: 1000 * 60 * 60 * 24, // 24h — keep cache even after unmount
      networkMode: "offlineFirst", // Return cached data immediately
      retry: (failureCount, error) => {
        if (error.response?.status === 401) return false;
        return failureCount < 3;
      },
    },
    mutations: {
      networkMode: "offlineFirst",
    },
  },
});
```

## 19. Component Architecture Rules

1. **Every component is `React.FC<Props>` with explicit interface.**
2. **No `any` types anywhere.** Use `unknown` + type guards if needed.
3. **All event handlers**: `useCallback` when passed to children.
4. **Heavy computations**: `useMemo`.
5. **Minimum touch target**: 44×44pt on every interactive element.
6. **`cursor: pointer`** equivalent on mobile: `activeOpacity={0.7}` on `TouchableOpacity`.
7. **Accessibility**: every icon button gets `accessibilityLabel`. Images get `accessibilityLabel`.
8. **Loading states**: Never use `if (isLoading) return <Spinner />` at screen level.
   Instead, show skeleton placeholders that match the final layout (prevents CLS equivalent — layout jump).
9. **Error states**: Inline error messages near the relevant field, not just toasts.
10. **Haptic feedback**: Every destructive action (delete, logout) gets `Haptics.notificationAsync(NotificationFeedbackType.Warning)`.
11. **Animations**: Use `react-native-reanimated` for all animations. No `Animated` API.
    - Duration: 150–300ms
    - Easing: `Easing.out(Easing.cubic)`
    - Use `withTiming`, `withSpring` appropriately
12. **Images**: Always specify `width` and `height` to prevent layout jumps.
13. **Lists**: Always use `FlatList` or `FlashList` (never `ScrollView` + `.map()` for long lists).
    - `FlashList` from `@shopify/flash-list` is preferred for very long transaction lists.
14. **Keyboard**: Wrap all forms in the custom `KeyboardAvoidingView` wrapper.
15. **Safe areas**: Every screen root wraps in `SafeAreaView` or uses `useSafeAreaInsets()`.

## 22. Things NOT to Do

- ❌ Do NOT touch `frontend/` or `backend/` — they stay exactly as they are
- ❌ Do NOT use WebView for any screen (all native)
- ❌ Do NOT use `AsyncStorage` for secrets — always `expo-secure-store`
- ❌ Do NOT use `localStorage` or `window.*` anywhere in mobile code
- ❌ Do NOT copy web colors/typography — the mobile design system is completely independent
- ❌ Do NOT use `if (isLoading) return <Spinner />` at screen level — use skeletons
- ❌ Do NOT use emoji icons — use `lucide-react-native` for all icons
- ❌ Do NOT use inline styles for anything that repeats — use `StyleSheet.create()`
- ❌ Do NOT use `ScrollView + .map()` for transaction lists — use `FlashList`
- ❌ Do NOT skip accessibility labels on icon buttons
- ❌ Do NOT use the `any` type — strict TypeScript throughout
- ❌ Do NOT use `Animated` API — use `react-native-reanimated` exclusively
